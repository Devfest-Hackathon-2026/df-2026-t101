# 分担と日程

> **このドキュメントで決めたこと**
> 1. 大学の3Dプリンタは11/9・11/10だけ使える（11/7・11/8は使えない）。11/9の朝いちばんに試し刷り（ねじ・くり抜き・ゲージを1つの台にまとめる）と、アプリで作った握りの1回目を続けて刷り、11/10の朝にデモ用の最終版を刷る。直せる回数が1回しかないので、11/7・11/8はスライサーで刷れるかを確かめておく。
> 2. 作る順番は「MediaPipe＋1円玉＋カプセルで仮に通す → 11/8 20:00までにメッシュ復元（`hand-mesh`、Cloud Run GPU）を組み込む」。デプロイ版の角度はメッシュ復元だけで出し、MediaPipeでは代わりにしない。SAM 3D Bodyの重みの承認が一番の不安要素。
> 3. 分担は、A＝採寸（JSの採寸エンジン）、B＝3Dモデルと部品（印刷、手のモデルの組み立て）、C＝生成APIとAI（Google Cloudの設定）、D＝画面と提出物。毎日21:00に打ち合わせて、進め方と費用を確かめる。

関連：[README.md](README.md)、[architecture.md](architecture.md)

11/8 12:00の中間の通しで遅れが見えたら、次の順に落とす（キックオフで決める案）。

1. 写真2枚のモード（動画が読めない端末は、ほかの端末で撮る）
2. 手で置くモード

4. 雰囲気と模様（色は残す）

## 7. 設計レビューで追加した検証項目

以下は実装時の完了条件で、設計書の修正だけでは合格としない。B6・C4・C5・D3・D4と採寸スキーマの検証に含める。

| 対象 | 入力・操作 | 期待する結果 |
|---|---|---|
| 楕円の肉厚（B5・C4） | 長径18mm、楕円率0.7、溝深さ2mm、穴径7.1mm | 短径側0.75mmなのでR4不合格。楕円率1.0の場合は3.45mmとして判定。3mmの境界も確かめる |
| すき間の探索（B6） | 既知の閉じた領域の内点と外点。外点をさらに遠ざける。自己交差・面積0・空の領域も用意する | 外点は距離によらず候補から除外。有効な円は領域内に収まる。不正な領域は中心と径がnull、`CAVITY_OPEN` となり、`fitted` を選べない |
| 承認対象の固定（C4・D3・D4） | 張り出しの大きい版でOTに頼む。依頼のあと、デプロイで描画のコンテナを新しくしてから承認する。依頼時と異なるハッシュで承認を送る | 依頼の時点で `RENDER_FAILED` になり、依頼されない。コンテナが変わっても、依頼済みの版は描き直さずに承認でき、公開される `print.stl` の `print_sha256` が依頼時と同じ。ハッシュ不一致は `STALE_DESIGN` |
| 採寸入力（A3・C4） | 正常な動画・写真の採寸、0・負・上限超過の長さと半径、各指の付け根の欠落、座標・フレーム数の不整合、非有限値、範囲外のoverride | 正常値だけ受理。不正値は手のモデルを組み立てる前に `MEASUREMENT_INVALID` とフィールド別のdetailsを返す |
| AIの確認結果（C4・C6） | `verdict=revise`、問題あり、`changes=[]`。微調整後のrevise、okと不合格チェックの矛盾も用意する | 修正案のないreviseと微調整後のreviseは `needs_attention`。指摘が画面とOTに残る。ok＋lowの指摘だけなら `ready`（指摘はメモとして残る）。ok なのに high・medium の指摘や不合格のチェックがあれば `needs_attention`（`AI_OUTPUT_INVALID` にしない）。C1〜C5の欠落は聞き直す |
| 異常終了と再送（C4・D3） | 生成の途中でインスタンスを止める。300秒たってから `recover` を呼ぶ／新しく生成を始める。処理中にもう一度ボタンを押す・別の端末から送る | 期限切れの印が回収され、版が `failed` になり、新しく生成できる。処理中の二重送信は `409 CONFLICT`。回収された古い処理が後から戻っても、版や進み具合を上書きしない |
| GPUの予算制御（C5・E1・E2） | HTTPで直接連続呼び出し。日次上限の直前で2つ同時に呼ぶ。推論のタイムアウト。共通設定をfalse・未設定・読めない状態にする | 上限の確認と加算が1つのトランザクションで行われ、上限を超えて始まらない。失敗・再試行も1回に数え、1回$0.40が足される。推論は60秒で中断。停止・上限では推論を始めず、自動再試行もしない |

| メッシュ復元の必須（C4・E1） | 結果トークンなし、署名の違うトークン、別のケースのトークン、角度を書き換えた採寸JSONを `PUT measurement` に送る。同意の記録がないケースで `hand-mesh` を呼ぶ | どれも `422`。同意の記録がなければ `CONSENT_REQUIRED` |
