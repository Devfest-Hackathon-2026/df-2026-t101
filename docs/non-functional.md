# 非機能要件

> **このドキュメントで決めたこと**
> 1. 財源は2つ（ハッカソンの20ドル、個人のクレジット約50,600円）。まずハッカソンの20ドルに収まるよう、開発中はモックと安いモデルを使い、Gemini 4 Argonは調整とデモに絞る。足りない分は個人のクレジットで払う。見積もりは定価で行い、予算アラートに加えて、アプリ側でも1日の概算コストで生成を止める。
> 2. 形の生成の目標は、最初のプレビューまで60秒（中央値）、最大150秒。初回の手のモデルの読み込みは、Wi-Fiで10秒以内。
> 3. 手の映像は、生成APIにもGeminiにも渡さない。端末の外に出るのは、手を切り抜いたフレーム（最大8枚）だけで、全員から同意を得て、角度の推定（`hand-mesh`）のためだけに使い、保存しない。

関連：[architecture.md](architecture.md)、[generation-pipeline.md](generation-pipeline.md)、[data-model.md](data-model.md)

### 2.5 どのクレジットで何を動かすか

| 財源 | 金額 | 使い道 |
|---|---|---|
| ハッカソンの配布クレジット（クーポンコード） | 20ドル | 個人の請求先アカウントで引き換える |
| 個人のGoogle Cloudクレジット | 約50,600円（¥47,462＋¥3,165）。使い切ると登録したカードに請求される | 同じ請求先アカウントに入っている |

- 決めたこと：クーポンを個人の請求先アカウントで引き換え、2つのクレジットを1つの請求先にまとめる。アプリと `hand-mesh` は同じ1つのプロジェクトに置き、その請求先につなぐ（[ADR-0009](adr/0009-gpu-placement.md)）
- 理由：請求先を付け替える手間と、プロジェクトをまたいだ呼び出しの不確かさがなくなる
- 引き受けること：どちらのクレジットから先に減るかを、分けて見られない。費用は総額で見張る
- 要確認：クーポンの規約で、使えるサービス（AI Studioには使えないとされている）や、引き換える請求先アカウントに制限がないか。引き換える前に読む
- 円とドルの換算は、1ドル＝150円の仮定（実際のレートで要確認）

### 2.4 予算を超えないための仕組み

| 仕組み | 設定 | 補足 |
|---|---|---|
| 予算アラート | 個人の請求先アカウント（円建て）に、3,000円（≒ハッカソンの20ドルを使い切った目安）・5,000円・10,000円・30,000円の予算。通知先は4人全員 | 予算は支出に上限をかけない（通知するだけ）。最初の通知まで数時間かかることがある。既定ではクレジットを差し引いた額で判定するので、**クレジットを含めない（差し引かない）設定にして、総額で判定する**。クレジットの消費額そのものでアラートを出す機能は、確かめられなかった |
| 毎日の確認 | 毎日21:00の打ち合わせで、Cloud Consoleの請求の画面と、Cloud Runの最小台数を確かめる | 請求データの遅れと、GPUの最小台数の放置に備える |
| アプリの1日の上限 | `usage/{日付}.estimated_cost_usd` が `DAILY_COST_LIMIT_USD`（既定$4）を超えたら、その日は生成を止める | 請求データの遅れに左右されない |
| 回数の上限 | 1人1日あたり生成10回・微調整30回・聞き取り60回。全体で1日あたり生成100回 | 審査員が試しても、予算を使い切らない |
| 停止スイッチ | `GENERATION_ENABLED=false` | 予算が75%を超えたら入れるかどうかを判断する |
| 課金の自動停止 | 使わない | 予算を超えたら課金アカウントを外す公式の方法（Pub/Sub＋関数）はあるが、全サービスが止まり、リソースが消えるおそれがあるため。デモの直前に止まる危険の方が大きい |
| インスタンスの上限 | 最大3 | 想定外のアクセスで増えすぎないように |

## 3. セキュリティ

| 項目 | 決めたこと |
|---|---|
| 秘密情報 | Geminiはサービスアカウントで呼ぶので、APIキーを使わない。サービスアカウントの鍵ファイルは作らない（手元では `gcloud auth application-default login` を使う）。Firebaseのウェブ用の設定値は秘密ではないが、チームの決まりに合わせてリポジトリには入れず、`--dart-define-from-file`（`env/*.json`、`.gitignore` に入れる）で渡す。見本として `env/example.json` だけを入れる。APIキーには、HTTPリファラーと使えるAPIの制限をかける |
| 認証 | Googleログインだけを使う（匿名ログインは、スマホとPCで引き継げないため使わない）。生成APIは、すべてのリクエストでIDトークンを検証する |
| 権限 | ケースは持ち主と、依頼されたOTだけが読める。OTかどうかは `therapists` の許可リストで決める。ブラウザからFirestore・Storageには書き込めない（[data-model.md §4](data-model.md#4-セキュリティルールの方針)） |
| 入力の検証 | すべての入力をPydanticで型と範囲を確かめる。チャットの文は1回500文字まで |
| AIの出力 | Geminiの出力は、スキーマと範囲チェックを通るまで使わない。OpenSCADに渡すのは、サーバーが型付きの値から作った `-D` の引数だけで、AIの文字列をコードやコマンドに混ぜない。プロンプトインジェクション（チャットで「範囲を無視して」などと書く）があっても、範囲チェックで止まる |
| OpenSCAD | ユーザーやAIが書いたコードは実行しない。ジョブごとに作業フォルダを分け、60秒で打ち切る。コンテナは非rootユーザーで動かす |
| 通信 | HTTPSのみ。CORSは自分たちのHostingのURLだけを許す |
| 乱用対策 | 回数の上限、1日のコストの上限、停止スイッチ。App Check（reCAPTCHA Enterprise。月1万回まで無料）は拡張機能 |
| ログ | ログに残すのは、ID、処理時間、トークン数、エラーコードだけ。チャットの文と採寸の数値はログに出さない |
| 依存関係 | Python・Dart・JavaScriptのライブラリは、バージョンを固定する |
| 提出前 | 提出用のリポジトリにpushする前に、手元で秘密情報の検査を行う |

## 4. プライバシー

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 手の動画・写真 | ブラウザのメモリの中だけで扱い、送らない・保存しない。手の検出と1円玉の切り出しは、端末の中のMediaPipeで行う。MediaPipeの本体とモデルは自分たちのHostingから配る | 手の映像は体の情報で、他人に見られたくない人がいる。送る口がないことで、仕組みとして守る |
| 手のメッシュ復元 | 撮影の前に全員から同意を得て（同意しないと採寸に進めない）、手を切り抜いたフレーム（最大8枚、長い辺512px）を、ブラウザから `hand-mesh` に直接送る。メモリの中だけで処理し、保存しない・ログに残さない。返すのは角度だけ。処理はシンガポールで行う（[ADR-0008](adr/0008-hand-model-capsules.md)） | 角度の精度を上げるため。手の映像は、病気や障害が分かる情報になりうるので、送る内容をはっきり示して同意を得る（要配慮個人情報に当たるかは要確認） |
| サーバーに送るもの | 聞き取りの文、採寸の数値（mm・度）、色と模様の選択 | — |
| Geminiに渡すもの | 聞き取りの文、採寸の数値、部品の引数、3Dモデルの画像。名前・メールアドレス・写真は渡さない | 必要なものだけを渡す |
| Geminiの処理場所 | `global` のため、日本の外で処理されることがある | Argonが東京で使えないため。渡すのは上の最小限の情報だけにする。国内での処理が必要になったら、東京で使えるモデル（`gemini-2.5-flash` など）に切り替える |
| AIの学習への利用 | 公式に「事前の許可や指示なしに、顧客のデータをAI・MLモデルの学習や調整に使わない」と書かれている（Agent Platformのデータの扱いのページ、Service Specific Terms 第18条）。ピッチで述べてよい | — |
| Geminiのキャッシュ | 送った内容は、既定で最長24時間メモリにキャッシュされる。プロジェクトの `cacheConfig` を `disableCache: true` にして止める（Cがデプロイのときに設定）。リクエストと応答の記録（request-response logging）は既定で無効のままにする。不正利用の監視のために、怪しいと判定されたプロンプトは最長90日保存されることがある | 健康に関わる会話を、要らないところに残さないため |
| 病名などの情報 | S0とS2に「病名などの詳しい情報は入れなくて大丈夫です」と書く | 要らない健康情報を集めない |
| 同意 | 初めて撮る前に、何を送り何を送らないかを1画面で示し、同意を得る。同意しない場合は採寸に進めない | — |
| 保存期間 | 審査が終わったら（2026年12月まで）、デモのデータを消す | — |

## 6. アクセシビリティ

- 起動時に `SemanticsBinding.instance.ensureSemantics()` を呼び、読み上げ用の情報を有効にする（Flutter Webは既定で無効）
- 押せる範囲は48px以上。ドラッグする点のハンドルは見た目より大きく反応させる
- 文字入力には選択肢を添え、音声入力（OSの機能）を案内する
- 色だけで状態を伝えない
- 片手で操作できるよう、主なボタンは画面の下に置く

## 7. 保守性・拡張性

| 項目 | 決めたこと |
|---|---|
| 唯一の正 | 部品と引数は `scad/catalog.json`、データの形は `schemas/*.schema.json`。範囲チェック、プロンプト、画面のスライダーは、ここから読む |
| 部品の追加 | 部品を足すときは、OpenSCADのモジュール・`catalog.json`・試し刷りをそろえる。Geminiに部品を作らせないので、足した部品は必ず人が確かめたものになる |
| プロンプト | ファイルで版を管理し、版を版（design）に記録する。決まった入力5パターンで比べてから入れ替える |
| モデルの切り替え | `GEMINI_MODEL` と `GEMINI_LOCATION` だけで切り替えられるようにする |
| テスト | 採寸の計算（Dart）、範囲チェックとコマンドの組み立て（Python）、セキュリティルール（エミュレータ）に単体テストを書く |
| 設計の記録 | 判断はADRに残す（[adr/](adr/)） |
