# ADR-0001：Geminiには部品と寸法のJSONを出力させる（案A）

> **このドキュメントで決めたこと**
> 1. Geminiには、部品の種類と寸法をJSON（決まったスキーマ）で出力させる。OpenSCADのコードは書かせない。
> 2. サーバーは、人が作って試し刷りした部品のファイル（`main.scad`）に、範囲チェックを通った数値を `-D` で渡すだけにする。
> 3. 理由は、崩れにくさ・説明のしやすさ・実装の速さのすべてで案Aが上回り、さらに本作のピッチの軸（寸法を保証する／印刷できる／臨床家が信頼できる）にそのまま答えられるため。

- 状態：採用
- 日付：2026-11-07
- 関連：[generation-pipeline.md](../generation-pipeline.md)、[parts-library.md](../parts-library.md)

## 背景

Geminiに形を決めさせる方法として、次の2つを比べた。

- **案A**：Geminiは、部品の名前と寸法をJSONで出す。サーバーがそれを検査し、テンプレート（`scad/main.scad`）に数値を差し込んでOpenSCADで形にする
- **案B**：Gemini自身がOpenSCADのコードを書き、サーバーはそれをそのまま実行する

先行研究（ASSETS 2025、Aflatoony ら）では、画像生成AIと画像から3Dへの変換で自助具を作っている。そこで挙げられた課題は「出力が画一的」「AIの出力を信頼しきれない」などで、前身の研究では「寸法の入力が難しく、出力が不正確になる」とも報告されている。本作は、この課題に答えることを軸にしている。

## 比較

| 観点 | 案A：JSON＋テンプレート | 案B：Geminiがコードを書く |
|---|---|---|
| 崩れにくさ | ◎ 出力の形はスキーマで縛れる。範囲外の値は機械的に検出して止められる。形そのものは人が試し刷りした部品なので、閉じた立体になり、刷れる | △ 文法の誤り、閉じていない立体、穴が開かない、といった失敗が起きうる。コードの中の寸法を検査するには、コードを解析する必要がある |
| 寸法の保証 | ◎ 「くぼみの位置＝採寸値＋14mm」のように、採寸値からの対応を式で決められ、AIが動かせる幅も決められる | × コードの中の数値が採寸値と合っているかを、機械的に確かめにくい |
| 安全性 | ◎ 角の丸み1.5mm以上、壁の厚さ2mm以上などを、部品の側で必ず守らせられる | △ 毎回コードを読んで確かめないと守られている保証がない。任意のコードを実行することになり、極端に重い形を作られて処理が止まる危険もある |
| 説明のしやすさ（OT向け） | ◎ 引数ごとに「値・範囲・決め方（採寸／AI）・理由」の表をそのまま出せる | × OTにOpenSCADのコードを読んでもらうのは現実的でない |
| 実装の速さ | ◎ 構造化出力（`response_json_schema`）と、数値の差し込みだけで済む。テストも書きやすい | △ 失敗したときの聞き直し、コードの検査、隔離して実行する仕組みが要る |
| コスト | ◎ 出力が短い（引数の一覧だけ） | △ コードは長く、聞き直しも増える |
| 表現力 | △ カタログにある部品の範囲でしか作れない | ◎ どんな形でも作れる可能性がある |

## 決定

案Aを採用する。

- Geminiは「部品選び」と「寸法決め」をJSONで返し、理由を引数ごとに付ける
- サーバーは、範囲チェック（[generation-pipeline.md §4](../generation-pipeline.md#4-範囲チェック)）を通った値だけを `-D` で `main.scad` に渡す。Geminiの文字列をコマンドやコードに入れない
- 「画像での確認」でも、Geminiが返すのはJSONの「直す引数と値」だけにする

## 理由（ひとことで）

「形を作るのは人、決めるのはAI、確かめるのはルールとOT」と役割を分けることで、寸法・印刷・信頼の3つの課題に、仕組みとして答えられる。これは「なぜその技術の使い方なのか」を説明する材料にもなる。

## 引き受けること（トレードオフ）

- 作れる道具の種類は、カタログの部品で決まる。これに対しては、ねじ締め式の先端（[ADR-0005](0005-screw-collet-tool-holder.md)）で、1つの握りで筆・ペン・スプーンなど多くの道具に対応する
- 部品を足すには、人がOpenSCADのモジュールを書いて試し刷りする手間がかかる

## 見直す条件

- カタログにない形の要望が多く集まったら、「Geminiに新しい部品の下書きを書かせ、人が確かめて試し刷りしてからカタログに足す」という、開発時だけ案Bを使う流れを検討する。利用者が使うときに、AIが書いたコードを実行することはしない
