# ADR-0014：1つのカバーに、道具ごとの取り付け具（C字クリップ）を複数持たせる。あとから足せる

> **このドキュメントで決めたこと**
> 1. 1つの版（カバーは1つ）に、道具ごとのC字クリップ（取り付け具）を複数持たせる。聞き取りで道具を1つ以上選べるようにし、道具ごとに柄の太さを聞き、角度はAIが道具ごとに選ぶ。
> 2. できあがった版から「取り付け具を足す」で、カバーを作り直さずに、別の道具のクリップを足せる。足すと新しい版になり、OTの確認はもう一度頼む（デモのケースは省略）。カバーのファイルは前の版と同じものを使う。
> 3. 取り付け具はすべて丸い柄用のC字クリップにそろえる（平たい柄用の取り付け具は作らない）。道具の選択肢（筆・ペン・スプーン・その他）は残す。

- 状態：採用（2026-11-09、チームの決定）。実装済み（2026-11-09。上限4つは `api/app/attachments.py` の `MAX_ATTACHMENTS` と `app/lib/core/models/attachments.dart` の `maxAttachments`）
- 日付：2026-11-09
- 関連：[ADR-0011](0011-dorsal-cover.md)（カバー）、[ADR-0012](0012-c-clip-dovetail.md)（C字クリップとアリ溝のレール）、[ADR-0013](0013-clip-angle-variants.md)（角度違いのクリップの差し替え）、[screens.md](../screens.md) S2・S7・S10、[api.md](../api.md) §3.2・§3.4〜§3.7・§3.11、[data-model.md](../data-model.md)、[generation-pipeline.md](../generation-pipeline.md)

## 背景

- 今は1つのケースで道具を1つしか選べない。ペンで作ったあとにスプーンでも使いたいときは、ケースを作り直す（撮影・手の3D・カバーの生成をもう一度）しかない
- カバーの形は道具によって変わらない。どの道具のクリップも、カバーの同じアリ溝のレールに差し込む（[ADR-0012](0012-c-clip-dovetail.md)）。道具を替えるのに要るのは、クリップの差し替えだけ
- 道具ごとに、柄の太さ（クリップの内径）と、ふさわしい角度（[ADR-0013](0013-clip-angle-variants.md)。筆70・ペン60）が違う。なので、道具ごとに別のクリップが要る
- 使う人の声：作るときに鉛筆とスプーンの両方のクリップを作りたい。使っているうちに、あとからクリップを足したい

## 目標・目標にしないこと・失敗とみなすこと

| 区分 | 中身 |
|---|---|
| 目標 | 作るときに道具を複数選ぶと、カバー1つと道具ごとのクリップができる。プレビューで道具ごとのクリップを切り替えて見られ、刷る前に全部のクリップをダウンロードできる |
| 目標 | できあがった版に、道具と太さを指定してクリップを足せる。カバーは描き直さず、刷り直しも要らない |
| 目標 | 道具ごとに角度をAIが選び、理由を書く。ユーザーはクリップごとに角度を選び直せる |
| 目標にしない | 平たい柄用の取り付け具（差し込み口など）。平たい柄の道具は、太柄スポンジなどで丸い柄にしてから使ってもらう |
| 目標にしない | クリップを外す（版から取り付け具を減らす）操作。足すだけにする |
| 目標にしない | 2つのクリップを同時にレールに付けること。クリップは差し替えて使う（同時に付けたときの当たりは考えない） |
| 目標にしない | スプーン専用の角度（すくう面を水平に保つための浅い角度）。スプーンも60／70／80度の中からAIが選ぶ（チームの決定） |
| 失敗とみなす | 取り付け具を足しただけでカバーの形（`cover_shell_sha256`）が変わる、またはカバーのSTLが変わる（刷り直しが要ってしまう） |
| 失敗とみなす | 足したクリップが、OTの確認を通らずに印刷用STLとして渡る（デモのケースを除く）。安全の決まり（[README.md](../README.md) の「安全」）を崩す |
| 失敗とみなす | 道具が1つだけのケース（今までのケース・今までの流れ）が動かなくなる、または見た目と結果が変わる |

## 決定

### 1. 道具と取り付け具

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 取り付け具の種類 | すべて丸い柄用のC字クリップ（今の `c_clip`）。平たい柄の道具の取り付け具は作らない | 試し刷りでしめしろを決める仕組み（2026-11-10 の時点で、今の版のクリップは刷っておらず、しめしろは仮のまま）と、作っておいた固定STLのライブラリ（[ADR-0012](0012-c-clip-dovetail.md) の4.）をそのまま使えるため |
| 道具の選択肢 | 今のまま（筆・ペン・スプーン・その他）。やりたいこと（`activity`）と道具（`tool_type`）の組み合わせも今のまま | AIが角度を選ぶ手がかりと、ケースの名前に使うため（チームの決定） |
| 1つの取り付け具が持つもの | 道具（`tool_type`）、やりたいこと（`activity`）、柄の太さ（`tool_d_mm`。区分で答えたときは今と同じく推定値と `assumptions`）、角度（`angle_deg`）と角度の出どころ・理由 | 道具ごとにクリップの内径と角度が違うため |
| 主な取り付け具 | 選んだ道具のうち、最初の**丸い柄**の道具を「主な取り付け具」とする。確認用画像（Geminiの画像での確認に使う4枚）、今までの1つのクリップを前提とした所（`params` の `c_clip`、`clip_angle_deg`、`clip`、`tool`）、要求の今までの項目（`tool_type`・`tool_d_mm`・`tool_shaft_shape` など）は、主な取り付け具の値にする。ケースの名前だけは、最初に選んだ道具から付ける（平たい柄でも）（2026-11-09、作る人の問いへの答え。Claudeの判断） | 道具が1つのケースと同じ見た目・同じ結果にするため。最初の道具が平たい柄でも、今の範囲チェックが `DESIGN_INFEASIBLE` にしないため |
| 数の上限 | 1つの版に4つまで。同じ道具を太さ違いで2つ持つのもよい（例：細いペンと太いペン） | 描く時間と画面の長さを抑えるため。4は仮の値で、作る人が変えてよい |
| 平たい柄 | 道具ごとに柄の形を聞く。平たい柄の道具は、その取り付け具だけ作らず、画面で「平たい柄はクリップで挟めません。太柄スポンジなどで丸くしてください」と知らせる。ほかの道具の取り付け具は作る。主な取り付け具が平たい柄で、ほかに丸い柄の道具がなければ、今と同じく作れない（`DESIGN_INFEASIBLE`） | 1つの道具のせいで、ほかの道具のクリップまで作れなくならないようにするため |

### 2. 聞き取り（S2）

| 項目 | 決めたこと |
|---|---|
| 道具の質問（今の質問1「何をしたいですか」） | 1つ以上選べるようにする。選んだ順に並べ、最初のものを主な取り付け具にする。「その他」を選んだときの任意のチャットと `activity_ja` の扱いは今のまま |
| 柄の太さ・形の質問（今の質問3・4） | 選んだ道具ごとに聞く（道具の名前を見出しに出す）。答え方（mmで入れる／区分で選ぶ）は今のまま |
| まとめ（S2c） | 道具ごとに、道具・太さ・形を1行ずつ出し、それぞれ鉛筆のボタンで直せる |
| 保存の形 | `PUT /v1/cases/{case_id}/requirements` に、道具の一覧（`tools`：道具・やりたいこと・太さ・区分・柄の形の組の配列、1〜4個）を足す。今の `activity`・`tool_type`・`tool_d_mm`・`tool_shaft_size`・`tool_shaft_shape` は残し、主な取り付け具（`tools` の最初）と同じ値を入れる。`tools` がない要求（今までの画面）は、今の項目から1つの道具として扱う |
| 開き直したとき | 保存済みの `tools` から答えを戻す（2026-11-09 に入れた「前の答えを戻す」と同じ考え方） |

### 3. 形を作る（生成API）

| 項目 | 決めたこと |
|---|---|
| 版の持ち方 | 版に、取り付け具の一覧（`attachments`）を持たせる。1つの取り付け具ごとに：取り付け具のID、道具・やりたいこと・太さ・角度と出どころ・理由、プレビュー用と印刷用のクリップのファイル、道具の軸（3D表示の棒）、そのクリップの検査の結果（R6f：クリップの開き、R6h：道具の通り道） |
| 今までの項目 | 今の `params` の `c_clip`、`clip_angle_deg`、`clip`、`tool`、`files.parts.c_clip` は残し、主な取り付け具と同じ値を入れる（今の画面・今のテスト・今までの版がそのまま動くように） |
| 角度の決め方 | Geminiの寸法決め（`dimension`）が、取り付け具ごとに角度（60／70／80）と理由を出す。プロンプトの版を上げる（`dimension.v2`。2026-11-10 に理由の文に項目名を書かせないよう直し、今は `dimension.v3`・`attachment.v2`・`system.v2`。`api/app/gemini/__init__.py` の `PROMPT_VERSIONS`）。モック（`GEMINI_MODE=mock`）は今の道具ごとの目安（筆70・ペン60・スプーン60）を使う。範囲チェック（R1〜R5）は取り付け具ごとに当てる |
| クリップを描く | 取り付け具ごとに、今と同じ方法（作っておいた固定STLのライブラリにあれば持ってくる、なければOpenSCADで描く）でクリップを作る。カバーと殻は1回だけ作る |
| 描いたあとの検査 | カバーの検査（R6a〜R6e）は1回。クリップの検査（R6f）と道具の通り道（R6h）は取り付け具ごと。どれかの取り付け具で R6h に落ちたら、今と同じく `needs_attention` にし、どの道具のクリップかを `unresolved_issues` に書く（R6h は注意で、印刷用STLは作れる） |
| 取り付け具だけが落ちたとき | （Claudeの判断）作るとき：ある取り付け具だけが、範囲チェックの致命的な違反・R6f（クリップの開き）・描けない（OpenSCAD の失敗）のどれかになったら、その取り付け具を版から外し、「◯◯のクリップは作れませんでした（理由）」を `unresolved_issues` に書いて、ほかの取り付け具とカバーで版を作る（平たい柄と同じ扱い）。主な取り付け具が外れたら、次の丸い柄の取り付け具を主に繰り上げる。全部外れたら、今と同じエラー（`DESIGN_INFEASIBLE` か `RENDER_FAILED`）。版に残った取り付け具に R6 の違反（注意を除く）がないので、印刷用STLは今の条件のまま作れる |
| 画像での確認（Gemini、最大3回） | 確認用画像4枚には、主な取り付け具のクリップと道具の棒だけを描く（今と同じ）。ほかの取り付け具は、決まった計算の検査（R6f・R6h）で確かめる |
| 印刷用STL（OTへの依頼・デモの印刷用データ） | カバー1つと、取り付け具ごとのクリップ。取り付け具が2つ以上のときは、ファイル名で道具と角度が分かるようにする（例：`c_clip_pen_60.stl`、`c_clip_spoon_60.stl`。同じ道具が2つなら太さも入れる）。取り付け具が1つのときは、今のファイル名（`c_clip_60.stl`、`c_clip_60.preview.stl`）のまま。`geometry_hash` と `print_sha256` は、全部の取り付け具を含めて作る（ハッシュの作り方は変えてよい。OTへの依頼のときに作って版に保存し、承認では保存した値と比べるので、今までの依頼には響かない）。OTの確認は、版の中の全部の部品をまとめて1回 |
| 道具が1つのケースの互換 | （Claudeの判断）「今と同じ」とは、カバーとクリップの形、画面の見た目、ファイル名が同じこと。`geometry_hash` の値は変わってよい |

### 4. あとから取り付け具を足す

| 項目 | 決めたこと |
|---|---|
| 入口 | プレビュー（S7）とダウンロード（S10）に「取り付け具を足す」。道具と、柄の太さ・形を選ぶ（聞き取りの道具ごとの質問と同じ部品を使う） |
| API | 微調整（`POST /v1/cases/{case_id}/designs/{design_id}/refine`）に、取り付け具を足す指示を加える（今の4種類の指示と同じく、1回に1つだけ）。版の状態の条件（`ready`／`needs_attention`）と、処理中の印・回数の上限（`refines`）は今の微調整と同じ |
| 版 | 新しい版を作る（今の「角度だけの変更」と同じ）。カバーは前の版の殻を使い、カバーのファイル（プレビュー用）と `cover_shell_sha256` は前の版と同じ。足したクリップの角度だけ、Geminiが選ぶ（モックでは道具ごとの目安）。画像での確認は行わない（今の角度だけの変更と同じ） |
| 聞き取りの記録 | 足した道具を、ケースの要求（`requirements.tools`）の最後に加える（次に作り直したときも、その道具のクリップができるように） |
| OTの確認 | 新しい版なので、確認済みは引き継がない。もう一度OTに頼む。デモのケースは「印刷用データを作る」で、そのまま印刷用STLを作れる。（Claudeの判断）確認済みの版に足したときも、今の「角度だけの変更」と同じく、ケースの今の版は新しい版になり、OTが確かめるまで S10 で印刷用STLは出ない（前の確認済みの組を出し続ける仕組みは作らない）。カバーは前の版と同じなので、すでに刷ったカバーをそのまま使えることを S7・S10 に書く |
| 角度の変更 | 今の「クリップの角度を選ぶ」を、取り付け具ごとにする（どの取り付け具の角度かを指示に入れる）。変えた取り付け具のクリップだけを描き直す |
| 太さの直し | （Claudeの判断）取り付け具ごとに、柄の太さも直せるようにする（角度の変更と同じく、どの取り付け具かを指示に入れ、新しい版で、そのクリップだけを描き直す。`requirements.tools` のその道具の太さも直す）。足した取り付け具の太さを間違えたときに、作り直し（カバーが変わるかもしれない）をしなくて済むように |
| 言葉・数値での微調整 | （Claudeの判断）S7 で選んでいる取り付け具のクリップの値に効かせる（微調整の指示に、取り付け具のIDを入れる）。カバーの値（厚み・切る位置など）は今と同じく全部に共通。Gemini の微調整（`refine`）には、カバーの値と、選んでいる取り付け具のクリップの値だけを渡す |
| 足すのに失敗したとき | （Claudeの判断）足す取り付け具が、範囲チェック・R6f・描けないのどれかで落ちたら、新しい版を作らずにエラーを返し（どの検査かを `details` に）、`requirements.tools` にも加えない。ケースは前の版のまま |

### 5. 画面

| 画面 | 決めたこと |
|---|---|
| S7 プレビュー | 3D表示の上に、取り付け具の切り替え（道具の名前のボタン。例「ペン」「スプーン」）。選んだ取り付け具のクリップと道具の棒を、手とカバーに重ねて出す。角度のボタン（60／70／80）は、選んでいる取り付け具の角度を変える。AIの角度の理由も、選んでいる取り付け具のものを出す。「取り付け具を足す」のボタン |
| S10 ダウンロード | カバーと、取り付け具ごとのクリップを1行ずつ（道具の名前・太さ・角度）。「まとめて」は全部をダウンロードする。印刷ガイドに「クリップは差し替えて使います。使う道具のクリップをレールに差し込みます」を足す |
| S9 OT確認 | 取り付け具ごとに、道具・太さ・角度と検査の結果を一覧で出す。確認項目は今のまま（版の中の全部の部品をまとめて確かめる） |
| S1 ホーム | ケースの名前は今のまま（主な取り付け具の道具から）。取り付け具が2つ以上あれば「ペン＋スプーン」のように出してよい（作る人が決めてよい） |
| モック（`MOCK_API=true`） | 取り付け具が2つの版を返せるようにし、画面だけで試せるようにする |

## 比べた案

| 案 | 中身 | 良い点 | 困る点 | 判断 |
|---|---|---|---|---|
| 道具ごとにケースを分ける（今のまま） | 道具が増えるたびに、撮影からやり直す | 作るものがない | 撮影・手の3D・カバーの生成を毎回やり直し、同じ形のカバーを何度も刷ることになる | 採らない |
| **1つの版に取り付け具を複数持たせる** | カバー1つ＋道具ごとのクリップ。あとから足すと新しい版 | カバーを共有できる。今の「角度だけの変更」（カバーを作り直さない）と同じ考え方で作れる | 版の形と画面に、取り付け具の一覧が加わる | **採用** |
| 取り付け具をケースに持たせ、版とは別に管理する | カバーの版とクリップを別々に確認・承認する | 足したクリップだけをOTが確かめればよい | 承認と印刷用STLの仕組み（`geometry_hash`、`print_sha256`、ルール）を2系統にすることになり、安全の決まりの確かめ方が複雑になる | 採らない |
| 平たい柄用の取り付け具も作る | スプーンの平たい柄を差し込む長方形の口 | 普通のスプーンがそのまま使える | 新しい部品と、締まり具合の試し刷りが要る | 採らない（丸い柄にそろえる。チームの決定） |

## 理由

1. **カバーは道具によらない**：レールが共通なので、カバーの殻・目印・検査を道具ごとにやり直す理由がない。今の「角度だけの変更」は、すでにカバーを使い回してクリップだけを描き直している
2. **安全の仕組みを1つのままにする**：取り付け具を版に入れれば、印刷用STLを渡す条件（OTの確認、デモの表示、ハッシュの確かめ）を今のまま使える
3. **今までのケースを壊さない**：主な取り付け具の値を今の項目にも入れるので、道具が1つのケースは今と同じに動く

## 引き受けること

| 危険 | 対策 |
|---|---|
| 確認済みの版に足すと、OTが確かめるまで、前の確認済みの印刷用STLもダウンロードできなくなる | 今の「角度だけの変更」と同じ動き。前の組はすでに刷ってある前提。困るようなら、最後の確認済みの組を出し続ける仕組みを足す（将来の改良） |
| クリップを足すたびにOTの確認をやり直すのは手間 | カバーが前の版と同じ（`cover_shell_sha256` が同じ）ことをOT画面に出し、確かめる所をクリップに絞れるようにする（作る人が見せ方を決めてよい） |
| 取り付け具が増えると、生成とダウンロードに時間がかかる | クリップは固定STLのライブラリから持ってくるので、1つあたり1秒未満の見込み（ライブラリの外の太さは、OpenSCADで数秒）。上限は4つ |
| スプーンを60〜80度で付けると、すくう面が傾いて食べにくいかもしれない | 今回はチームの決定で、ペンと同じ角度から選ぶ。使ってみて合わなければ、スプーン用の角度の選択肢を足す（将来の改良） |
| 道具の選択を複数にすると、聞き取りが長くなる | 道具ごとの質問は太さと形だけにする。道具が1つなら今と同じ長さ |
