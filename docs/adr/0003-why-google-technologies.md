# ADR-0003：Googleの技術を選んだ理由（Gemini、MediaPipe、Cloud Run、Firebase、Flutter）

> **このドキュメントで決めたこと**
> 1. 中核の技術は、Gemini 4 Argon（判断と確認）、MediaPipe（端末の中での採寸）、Cloud Run（OpenSCADを動かす）、Firebase（認証・データ・確認の門番）の4つ。画面はFlutterで作る。
> 2. どの技術についても、「本作のどの課題を、その技術のどの性質で解くのか」を1文で言えるようにする。審査の「Google技術の採用理由」と、ピッチの材料にする。
> 3. 確かめていない性質（例：AIの学習にデータを使わないこと）は、ピッチで言わない。要確認として残す。

- 状態：採用
- 日付：2026-11-07
- 関連：[architecture.md](../architecture.md)、[ADR-0001](0001-gemini-output-json-params.md)、[ADR-0002](0002-frontend-flutter-web.md)

## 1. まとめ（ピッチ用の1文）

| 技術 | 本作で何をするか | なぜその技術か（1文） |
|---|---|---|
| Gemini 4 Argon（Agent Platform） | 聞き取り、部品選び、寸法の調整と理由、できた形の画像での確認 | 1つのモデルで、会話・決まった形のJSONでの出力・画像を見ての確認まで行えるので、「決めた理由を説明できるAI」を1つの流れで作れるから |
| MediaPipe（Hand Landmarker） | 動画のフレームから手の21点を取る。撮影中に手の骨組みを重ねて、手が写っているかを示す。1円玉の検出で、手の上の丸（爪・関節）を外すのにも使う | ブラウザの中で動くので、手の動画を丸ごと送らずに採寸できるから（送るのは、同意を得た、切り抜いたフレーム数枚だけ） |
| Cloud Run（GPUを含む） | 生成API（Gemini＋範囲チェック＋OpenSCAD）、手のメッシュ復元（L4 GPU） | OpenSCADのような普通のプログラムをコンテナごと動かせて、使っていない間はお金がかからないから |
| Firebase | ログイン、データ、STLの保存、アプリの配信 | ルールで「通常の手順では、OTが確認するまで印刷用のデータを渡さない」を、サーバーのコードに頼らずに守れるから |
| Flutter | 画面（Web） | 同じコードでスマホのアプリにも広げられるから（アプリにすれば、公式のFlutter用MediaPipeパッケージでカメラの映像をその場で処理できる。Webでは採寸エンジンから `@mediapipe/tasks-vision` を直接呼ぶ） |

## 2. それぞれの理由

### 2.1 Gemini 4 Argon（Gemini Enterprise Agent Platform 経由）

- **使う性質**
  - 構造化出力（JSON Schemaで出力の形を縛る）。部品と寸法を、決まった形で受け取れる（[ADR-0001](0001-gemini-output-json-params.md)）
  - 画像の入力。できた形を4方向から描いた画像を見て、意図と合っているかを確かめさせる。「作って終わり」ではなく「作ったものを見て直す」流れを作れる
  - 思考レベルの調整（LOW／MEDIUM）。聞き取りは速く、寸法決めと確認は丁寧に、と使い分けて待ち時間とコストを調整する
  - 日本語の会話。高齢の人や家族にも分かる言葉で聞き返せる
- **Agent Platform経由にする理由**：配布されたクレジットはAI Studioに使えない。サービスアカウントで呼べるので、APIキーを持たずに済む
- **ほかの案を選ばなかった理由**：画像生成AIや、画像から3Dを作るモデルは、寸法を保証できない。先行研究（ASSETS 2025）でも、出力が画一的になることや、AIの出力を信頼しきれないことが課題として挙げられている
- **注意**：Argonは東京リージョンでは提供されていない（`global`／`us`／`eu` のみ）。Geminiに渡すのは数値・文・3Dの画像だけにする（[non-functional.md §4](../non-functional.md#4-プライバシー)）

### 2.2 MediaPipe（Hand Landmarker）

- **使う性質**
  - ブラウザの中（WebAssembly）で、動画の各フレームから手の21点を取れる。動画を丸ごとサーバーに送らずに済む
  - 指の関節ごとの点が取れるので、指の区間の長さ（1円玉で実寸にしたもの）を測れる。この長さで、手の3Dメッシュの大きさを合わせる（[ADR-0010](0010-hand-mesh-fusion.md)）
  - 2026-11-07 更新：最初は1円玉の切り出しに Interactive Segmenter を使う予定だったが、CPUでは1回約5秒かかって画面が止まり、GPUでは空のマスクが返ったのでやめた。1円玉の検出は OpenCV.js（Googleの技術ではない。Apache-2.0）に替えた（[ADR-0006](0006-coin-scale-reference.md)）
  - 公式のモデルカードに、地域・肌の色・性別ごとの評価が公開されている（誤差は手のひらの大きさの約5〜10%）。どのくらい信頼してよいかを数字で説明できる
- **ほかの案を選ばなかった理由**：写真をGeminiに送って関節を測らせる方法もあるが、手の写真を外に出すことになる。3Dスキャナーは、ほとんどの施設にない（作業療法士の調査でも、3Dプリンタを使ったことがあるのは4.4%で、壁の1つは「職場に設備がない」だった）
- **限界と対策**：曲がったままの指や、物を握った手は、モデルが苦手とする条件に近い。そのため、多くのフレームで集計し、3Dの手を本人と家族に見せて「ずれている」なら撮り直してもらい、OTの確認を挟む（[measurement.md](../measurement.md)）
- **手のメッシュ復元（Googleの技術ではない）との関係**：手の3Dメッシュ（形と姿勢）はメッシュ復元（SAM 3D Body）で作り、MediaPipeで測った長さで実寸にする（[ADR-0010](0010-hand-mesh-fusion.md)）。動かす場所はCloud Run GPU（[ADR-0008](0008-hand-model-capsules.md)、[ADR-0009](0009-gpu-placement.md)）。MediaPipeの角度は、OT画面に比較用として出す

### 2.3 Cloud Run

- **使う性質**
  - 自分で作ったコンテナを動かせる。OpenSCAD（CLIのプログラム）、Python、メッシュの検査を1つにまとめて置ける
  - 使っていない間は0台になり、お金がかからない。毎月の無料枠も大きい。GPUを含めても、2つのクレジット（ハッカソンの20ドルと個人のクレジット）の合計に収まる見込み
  - リクエストのタイムアウトを最大60分まで延ばせる。確認を3回くり返す生成（最大約170秒）でも途中で切れない
  - 東京リージョンに置ける
- **ほかの案を選ばなかった理由**：Cloud Run functions（関数）では、OpenSCADのような普通のプログラムを同梱しにくい。仮想マシンは、常に動かしておくとお金がかかる

### 2.4 Firebase（Authentication、Firestore、Cloud Storage、Hosting）

- **使う性質**
  - **Authentication**：Googleログインで、スマホ（撮影）とPC（プレビュー・印刷）を同じアカウントで引き継げる
  - **Firestore**：変更を待ち受けられるので、生成の進み具合（「画像で確認しています 2/3回目」）を、仕組みを作り込まずに画面へ流せる
  - **Cloud Storage＋ルール**：Storageのルールから、Firestoreの「確認済み」の印を読める。そのため「通常の手順では、OTが確認した版しか印刷用STLを読めない」という安全の約束を、ルールの側で保証できる
  - **Hosting**：HTTPSで配信できる（カメラとMediaPipeにはHTTPSが必要）。MediaPipeの本体とモデルも同じ場所から配れる
- **ほかの案を選ばなかった理由**：自前でデータベースと認証を作ると、3日では安全性を確かめきれない

### 2.5 Flutter（Web）

[ADR-0002](0002-frontend-flutter-web.md) を参照。要点：同じコードでアプリに広げられる、MediaPipeの公式Flutterパッケージがある、FirebaseとあわせてGoogleの技術で一貫して説明できる。

## 3. 「中核か」を示す材料

審査の「Google技術がプロダクトの中核か」には、次の事実で答える。

- **Geminiを外すと、流れが成り立たない**：要望から部品と寸法への変換、理由の説明、できた形の確認は、すべてGeminiが担う
- **MediaPipeを外すと、本人に合わせられない**：採寸ができず、プライバシーの約束も守れない
- **Firebaseのルールが、安全の約束を担う**：通常の手順では、OTの確認の門番になっている（デモのケースだけは、審査で最後まで見せるために確認を省略し、画面にそう示す）
- **Cloud Runの上で、Geminiの判断が、刷れる形になる**

## 4. 要確認（ピッチで言う前に確かめる）

- （確認済み）Agent Platformでは、事前の許可や指示なしに、顧客のデータを学習に使わない（データの扱いのページ、Service Specific Terms 第18条）
- 配布されたクレジットが、Agent Platform上のGeminiに使えること
- 採寸エンジン（`@mediapipe/tasks-vision`）が、iPhoneのSafariで動くこと（11/7に確かめる）
- 先行例の一覧と、確かめた範囲は [prior-art.md](../prior-art.md) にまとめた
- （確認済み）先行研究（ASSETS 2025）の本文には、寸法を正確に指定できないこと、印刷の向きと強度の課題、臨床家の信頼の問題、画一的な出力が書かれている（[prior-art.md](../prior-art.md)）
