# ADR-0009：メッシュ復元は、アプリと同じプロジェクトのCloud Run GPU（シンガポール、L4、最小0台）で動かす

> **このドキュメントで決めたこと**
> 1. 手のメッシュ復元（SAM 3D Body）は、生成APIとは別のCloud Run GPUサービス `hand-mesh` にする。設定は、asia-southeast1、L4、ゾーン冗長なし、4 vCPU・16 GiB、最小0台・最大1台。
> 2. 置き場所は、アプリと同じプロジェクトにする。ハッカソンのクーポンは、個人の請求先アカウントに入れて、クレジットを1つにまとめる。
> 3. 一番大きな事故は、最小台数を1のまま放置すること。最小台数は1にせず、温めは「呼び出して起こす」で行う。毎日21:00に、最小台数と費用を確かめる。

## Cloud Run GPUの条件（2026-11-07時点で公式ドキュメントを確認）

| 項目 | 内容 |
|---|---|
| GPUの種類 | NVIDIA L4（24GB）、NVIDIA RTX PRO 6000 Blackwell（96GB）。1インスタンスに1枚 |
| 東京 | どちらも**使えない** |
| L4のリージョン | asia-southeast1（シンガポール）、europe-west1、europe-west4、us-central1、us-east4、asia-south1（ムンバイ、招待制）。日本から一番近いのはシンガポール |
| L4の最低構成 | 4 vCPU・16 GiB（推奨は8 vCPU・32 GiB） |
| 割り当て | そのリージョンで初めてデプロイしたときに、ゾーン冗長なしのL4が3枚分つく |
| ゾーン冗長 | 新しいサービスでは**既定でオン**。オフにする指定が要る（オンだと高い）。gcloudとYAML・Terraformでは、指定の真偽が逆になるので注意 |
| 課金 | インスタンスベースの課金だけ。0台まで縮められる。最小台数を1以上にすると、待機中も全額かかる |
| 起動 | 約5秒＋モデルの読み込み。大きなモデルは、Cloud Storageに置いて起動時に取ってくるのが推奨（10GB未満ならイメージに入れてもよい）。起動の確認（startup probe）はGPUなら1800秒まで延ばせる |

料金（インスタンスベース、ドル建て）

| 項目 | us-central1など | asia-southeast1 |
|---|---|---|
| L4（ゾーン冗長なし） | $0.0001867/秒（約$0.67/時） | $0.00022404/秒（約$0.81/時） |
| CPU | $0.000018/vCPU秒（Tier 1） | $0.0000216/vCPU秒（Tier 2） |
| メモリ | $0.000002/GiB秒（Tier 1） | $0.0000024/GiB秒（Tier 2） |
| 合計（L4・4 vCPU・16 GiB） | 約$1.06/時 | 約$1.26/時 |
| 合計（L4・8 vCPU・32 GiB） | 約$1.45/時 | 約$1.70/時 |

検討メモにあった単価（$0.0001867/秒）は、米国・欧州のリージョンの値。シンガポールでは約20%高い。

## 比べた案

| 案 | 良い点 | 困る点 |
|---|---|---|
| A. 手元のGPU付きPC | 費用がかからない。すぐ試せる | デプロイ版で動かない。審査員が試せない |
| B. Cloud Run GPU（シンガポール） | デプロイ版で動く。0台まで縮められる。Googleの技術の上で動く | 日本から遠い（国外で処理される）。最小台数の放置で大きな費用がかかる。起動のたびにモデルの読み込みを待つ |

## 決定

Bにする。開発の最初の動作確認は、Aでもよい（同じコンテナを手元で動かす）。

- サービス名は `hand-mesh`。ブラウザから直接呼ぶ（生成APIは経由しない。[ADR-0008](0008-hand-model-capsules.md)）。FirebaseのIDトークンを検証し、CORSは自分たちのHostingのURLだけを許す
- 設定は、asia-southeast1、L4、ゾーン冗長なし、4 vCPU・16 GiB、最小0台・最大1台、同時に処理するリクエストは1、タイムアウトは120秒
- モデルの重みはCloud Storage（asia-southeast1のバケット）に置き、起動時に読み込む。重みはリポジトリにもコンテナイメージにも入れない
- ブラウザ側は、60秒以内に返事がなければMediaPipeの角度で進める（待たせすぎない）

## プロジェクトとクレジット

- ハッカソンのクーポンは、個人の請求先アカウント（個人のクレジット約50,600円が入っているもの）で引き換える。アプリ（Hosting・Firestore・Storage・生成API・Gemini）と `hand-mesh` は、同じ1つのプロジェクトに置く
- こうすると、請求先アカウントを付け替える手間と、プロジェクトをまたいだ呼び出し（公式に明記がなく要確認だった）の両方がなくなる
- 代わりに、どちらのクレジットから先に減るかを分けて見られない。そのため、費用は総額で見張る（[non-functional.md §2.4](../non-functional.md#24-予算を超えないための仕組み)）
- 要確認：クーポンの規約で、使えるサービスや請求先アカウントに制限がないか（引き換える前に読む）

## 一番大きな事故を防ぐ

最小台数を1のままにすると、最低構成でも1日約$30（約4,500円。1ドル150円の仮定）かかる。

- 最小台数は常に0にする。デモの30分前に1回呼んで起こし、5分おきに軽い呼び出しで起こしておく（審査の時間帯だけ）
- 毎日21:00の打ち合わせで、`gcloud run services describe hand-mesh` で最小台数を確かめる（チェックリスト）
- 請求先アカウントに、予算アラート（3,000円・5,000円・10,000円・30,000円）を付ける
