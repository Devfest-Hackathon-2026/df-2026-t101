# ADR-0004：カードの縮尺は、ユーザーが4隅にハンドルを合わせて出す

> **このドキュメントで決めたこと**
> 1. MVPでは、カードの4隅をユーザーがドラッグで合わせる。拡大鏡を出して合わせやすくし、4点から射影変換（ホモグラフィ）でmmに換算する。
> 2. 自動の検出は、時間があれば足す。足すときは、MediaPipeのInteractive Segmenterで「カードを1回タップ → 4隅の候補を置く → ユーザーが確かめる」形にする。自動の結果をそのまま使うことはしない。
> 3. 理由は、どんな写真でも必ず最後まで進めること、ユーザーがその場で正しさを確かめられること、3日で確実に作れること。

## 背景

写真の中のカード（85.60×53.98mm）から縮尺を出す。カードの4隅の位置がずれると、すべての寸法がずれる。手の写真は端末の外に出せないので、Geminiのようなサーバー側のAIには検出させられない。

## 比べた案

| 案 | 中身 | 良い点 | 困る点 |
|---|---|---|---|
| A. 4隅を手で合わせる | 4つのハンドルをドラッグする。拡大鏡を出す | 照明・背景・手との重なりに関係なく、必ず進める。合わせた場所がそのまま見えるので、正しさをその場で確かめられる。作るのが簡単 | ドラッグが4回×2枚要る。指が不自由な人には負担 |
| B. 画像処理で自動検出（OpenCV.js） | 輪郭を取り、四角形を探す | 操作が要らない | OpenCV.jsは約16MBと重い。白いカードを白い机に置いたとき、手がカードに重なったとき、光って反射したときに失敗しやすい。失敗すると結局Aが要る |
| C. 物体検出（MediaPipe Object Detector） | 学習済みのモデルでカードを探す | 軽い | 公式のモデル（COCOの80種類）に「カード」がない。自分で学習させる時間はない |
| D. タップ1回で切り出す（MediaPipe Interactive Segmenter） | カードを1回タップすると、カードの領域（マスク）が返る。そこから4隅を計算する | 操作が1回で済む。Googleの技術を使える | マスクから4隅を求める処理は自分で書く必要がある。1回のタップできれいに切り出せるかは確かめていない |

## 決定

MVPはAにする。Dは、11/9に時間が残っていれば「4隅の候補を自動で置く」機能として足す。どちらでも、最後はユーザーがハンドルの位置を確かめて「次へ」を押す。

## 理由

1. **必ず最後まで進める**：デモでも実際の利用でも、検出が失敗したら先に進めない、という状態を作らない
2. **確かめられる**：寸法の根拠になる点を、ユーザーやOTが目で見て直せることを大事にする（[measurement.md](../measurement.md) の「計算に使うのは、画面で確認・修正できる点だけ」という方針と同じ）
3. **精度**：拡大鏡を使えば1隅のずれは数px程度に収まる。カードの長い辺が800pxなら、誤差は約0.3%で、ほかの誤差（手の高さ、ランドマークのずれ）よりずっと小さい
4. **期間**：Aは半日で作れる。BやDは、失敗するときの扱いまで含めると1日以上かかりうる

## 指が不自由な人への配慮

- 撮影と採寸の操作は、家族やOTが代わりに行えるように案内する。片麻痺の人は、麻痺のない手で操作できる
- ハンドルは見た目より大きく反応させ、細かいタップは求めない
- 最初は4つのハンドルを写真の中央に置く。Dを足せたら、カードの近くに置く

## 見直す条件

- 11/9の検証で、4隅を合わせるのに1枚あたり30秒以上かかる人が多い場合は、Dを優先して足す
