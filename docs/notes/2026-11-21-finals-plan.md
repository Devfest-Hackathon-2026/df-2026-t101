## 2. 直すもの

### 2.1 アプリの中で発注まで終わらせる（いちばん大きい）：作った（2026-11-21。本番に出すのはこれから）

**今**：S10（[print_screen.dart](../../app/lib/features/print/print_screen.dart)）は、部品ごとのSTLのダウンロードと刷り方の案内まで。プリンタがない人は、自分で委託先を探すしかない。

**直すこと**：

- S10に「自分で刷る」と「刷ってもらう（発注）」の2つを置く
- 発注では、プリンタの機種・材料（カバーはPLA、クリップはPETG）・印刷設定をアプリが決める。利用者が入れるのは個数と届け先だけ
- 注文をFirestoreに保存する（部品のファイル、材料、設定、届け先、状態）。OTの確認が済むまで発注できない（今のSTLのダウンロードと同じ決まり）
- 受託する側の画面を作る。注文の一覧を見て、ファイルを取り出し、状態を「受付 → 造形中 → 発送済み」と進める。依頼した側の画面にも、その状態を出す
- あるとよいもの：自分で刷る人向けに、印刷設定入りの3MFを出す
- 支払いと実際の発送は作らない

**決めること**：

- 受託する側を誰として見せるか。デモではチームが受託者の役をする案がよい。実在の会社と提携しているようには見せない
- 固定するプリンタの機種（チームが実際に使っている機種）

### 2.2 フェルトで誤差を吸収する

**今**：フェルトは設計にすでに入っている。カバーと手のすき間 `HAND_CLEARANCE_MM` は1.5mmで、フェルトの厚さ `FELT_THICKNESS_MM` の1.0mmを含む。印刷ガイドにも「内側にフェルトを貼る」とある。ただし、[catalog.json](../../scad/catalog.json) ではどちらの値もまだ「仮」で、実物で確かめていない。

**直すこと**：

- 粘着付きのフェルトを買い、すき間を比べる試し刷り（`clearance_test`。すき間1.0／1.5／2.0mm）に貼ってかぶせて、2つの値を決める。印刷に時間がかかるので早めに始める
- 逃げ道として説明できる形にする。ゆるければ厚いフェルトに、きつければ薄いフェルトに替えるだけで直り、刷り直さなくてよい。合う厚さの範囲を、画面と印刷ガイドに出す
- 発注とつなげる。受託する側がフェルトを貼った完成品を送れば、受け取った人は何もしなくてよい
- スライドに「誤差がどこで出て、どこで吸収するか」を1枚で入れる（採寸と印刷で出る誤差を、カバーはフェルトで、クリップはしめしろとTPUの筒で吸収する）

### 2.3 手が不自由な人に向けたUIにする

**今**：主なボタンの最小の高さは56dp、文字のボタンは48dp（[theme.dart](../../app/lib/core/ui/theme.dart)、[widgets.dart](../../app/lib/core/ui/widgets.dart)）。

**直すこと**：

- 主なボタンを64〜72dpにし、文字も大きくして、ボタンどうしの間をあける
- 1つの画面で頼む操作を1つに絞る
- 3D表示を、ドラッグやピンチだけでなく「回す」ボタンでも回せるようにする
- 色の濃さの差（コントラスト）を確かめる
- 本人が触る画面（S2の聞き取り、S7の確認）から先に直す

ボタンの大きさはテーマでまとめて決めているので、`theme.dart` を変えるとアプリ全体に効く。

### 2.4 見た目をよくする

- 色・文字・余白をそろえ、ロゴの色をテーマに入れる
- いまどこまで進んだかの表示と、ホーム画面の第一印象を整える
- §2.3と同じく `theme.dart` から手をつけるので、2つはまとめて行う
- 新しいイラストやフォントを使ったら、著作物利用シートを直す

## 3. 追加する機能

§2の直しとつながり、3日半で作れる大きさのもの。§3.1と§3.2は入れる（2026-11-21に決めた）。§3.3は時間が余ったら。

### 3.1 「合わなかった」と伝えると、直して届く（使ったあとの報告）：入れる

- 部品が届いたあと（刷ったあと）、ケースの画面に「使ってみてどうでしたか」と大きなボタンを出す：ちょうどいい／ゆるい／きつい・痛い／赤くなった／道具が抜ける
- ゆるい・きつい：まずフェルトの厚さを替えるよう案内する（刷り直さない）。それでも合わなければ、S7の「もう少しゆるく／きつく」で新しい版を作り、OTの確認を通して、合わない部品だけ発注し直す
- 赤くなった：すぐ使うのをやめるよう出し、OTに相談するよう促す
- ねらい：品質の逃げ道を仕組みとして見せられる。フェルトと発注を1つの流れにできる。報告がたまれば「ちょうどいい」の割合を出せ、§2.5の証明の土台になると言える
- 大きさ：小〜中。画面1つとFirestoreの項目。直す処理は今あるものを使う

### 3.2 印刷時間・材料の量・金額の目安を出す：作った（2026-11-21、§2.1 と一緒に）

- S10と発注の画面に「カバー：約○g・約○時間／合計 約○円」を出す
- 部品の体積は、検査でもう計算している（[checks.py](../../api/app/geometry/checks.py) の R6a）。プリンタと材料を1つに決めるので、体積から重さ・時間・金額を概算できる
- 1回実際に刷った結果で合わせ、画面には「目安」と書く
- ねらい：3Dプリントを知らない人にも、刷るのにどれくらいかかるかが分かる。発注の流れが本物らしくなる
- 大きさ：小

### 3.3 声で答える（時間が余ったら）

- 今は、S2のチャットの欄で声を使えるのは、キーボードの音声入力だけ。そこに大きなマイクのボタンを置き、話した内容をそのままGeminiの聞き取りに渡す
- ねらい：手が不自由な本人が、手を使わずに答えられる。ユニバーサルデザインの指摘への、いちばん分かりやすい答え
- 大きさ：中。iPhoneのSafariで動くかを確かめる必要がある

## 7. 時間が余ったら試す案：3D表示を Flutter Scene にする

§2と§3が終わって時間が余ったら、別のブランチで試す。11/23の夜（機能を止める時点）までに今の表示と同じことができなければ、three.js のままで出す。

### 7.1 今の仕組み

- [viewer_3d.dart](../../app/lib/core/viewer/viewer_3d.dart) が `HtmlElementView` でページに `<div>` を置き、[viewer.js](../../app/web/js/viewer.js) が three.js（WebGL）でそこに描く。Flutter からは `dart:js_interop` で `window.jijoguViewer` を呼ぶ
- three.js は jsDelivr から読んでいる（[index.html](../../app/web/index.html)）
- Webでしか動かない。スマホのアプリにするなら、Webビューで包むか、作り直す

### 7.2 Flutter Scene でできるか

pub.dev の説明（0.24.3、2026-11-21に読んだ）では、今の機能は一通りできそう。実際に動かして確かめてはいない。

- Webで動く。専用のWebGL2の仕組みを持ち、設定は要らない。Flutter 3.47以上の stable で使える（手元は3.47.9）

| 今やっていること                               | Flutter Scene での方法                                                                                                |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 手の3D（GLB）をStorageから読む                 | `Node.fromGlbBytes` で、取ってきたデータをそのまま読める                                                              |
| カバー・クリップ（STL）を読む                  | STLは読めない。Dartで頂点を取り出して `MeshGeometry.fromArrays` で形を作るか、サーバーでGLBも出す                     |
| 手を半透明で重ねる                             | 材料の `alphaMode` を `blend` にし、`baseColorFactor` の透明度を下げる                                                |
| 色を変える                                     | `baseColorFactor` を実行中に変えられる                                                                                |
| 道具の棒、手の点                               | `MeshGeometry` で自分で作る                                                                                           |
| どの向きにも回す操作（今は TrackballControls） | 用意されていないようなので、Flutter のジェスチャで作る。そのぶん「回す」ボタン（§2.3）は同じ Flutter のコードで作れる |

### 7.3 よいところ

- 画面も3D表示も Flutter のコードだけで書ける。ボタンやジェスチャと3D表示をつなぐのが楽になる
- 同じコードでスマホのアプリ（iOS／Android）にも出せる。アプリにするなら、移す理由になる
- three.js を CDN から読まなくて済む

### 7.4 気をつけること

- 1.0より前の版で、版が上がると互換性がなくなることがある
- iPhone の Safari での動きと速さは分からない。今の three.js の表示は、iPhone で重くならないよう調整してある（画素の密度を2倍までにする、など）
- 今の表示と同じことができるまで、1〜2日かかる見込み
- スマホのアプリでは Flutter GPU を有効にする設定が要る（Webでは要らない）

### 7.5 試し方

別のブランチで、まず半日ほど。手のGLBとカバーのSTLを1つずつ出し、手を半透明で重ね、iPhone の Safari で回してみる。速さと見た目を three.js と比べて、続けて移すかを決める。移すと決めても、`impl` に入れるのは今の表示と同じことができてから。
